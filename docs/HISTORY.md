# 全量 HealthKit 历史记录（0.5.0）

只想在本机读取、按来源查看和导出 OPPO 睡眠，可使用首页新增入口，无需配置服务器。详见 [OPPO 睡眠历史说明](OPPO_HISTORY.md)。

## 升级

停止旧 Go 进程并退出 Xcode，在项目根目录：

```bash
git pull --ff-only origin main
bash setup-backend.sh
bash start-server.sh
```

另开终端进入同一根目录：

```bash
bash setup-ios.sh
```

Xcode 保持原 Team / Bundle ID，Command+R 覆盖安装 **0.5.0 (6)**。不卸载 App、不重建数据库、不填写 Token。仅更新服务端不会更新手机 UI。原 MySQL 配置保留；初始化只创建缺失的表，原摘要与历史数据不删除。旧 Python 回退服务没有历史接口。

## 手机

首页左上角「历史」有两个页面。

- **本机按日查看**：选择任意过去日期，点击读取。无需服务器；查询当前手机时区下的当日活动以及前一日中午到所选日中午的睡眠。今日首页和眼镜摘要不会被替换，也不会自动上传这个历史日。心率、运动卡片是截至所选日最近一次记录（30 天回看），全部逐条记录应使用第二页。
- **全部记录与同步**：明确提示会上传逐条健康记录。点击「开始 / 继续同步全部历史」。首次从 HealthKit 无日期谓词的起始锚点扫描；每批最多 200 个对象。保存的是现有 8 类：睡眠分类（含卧床/清醒/核心/深度/REM/未分类）、已保存运动、每日活动三环、步数、步行跑步距离、活动能量、锻炼分钟、心率数量样本。不是 Apple 健康所有可能的数据类型，不含 ECG 波形、运动路线、药物等。

首次请保持 App 前台、手机解锁、与 Mac 网络互通。运行期间关闭自动锁屏以方便导入，结束后恢复。可主动暂停；切入后台会请求停止，已确认批次保留。正在执行的系统查询/网络请求可能先结束；不承诺后台长时间运行。重新打开后点继续。进度显示本轮处理数量，不是假装预先知道全库总量。

后续对七种样本使用 HKAnchoredObjectQuery 读取新增/删除；活动三环没有锚点查询，重新读取所有可访问的每日摘要并更新。每种锚点仅在整批成功落库后持久化，失败可重试；服务地址或历史存储 epoch 变更会重新扫描。显式删除服务器数据会轮换 epoch，拒绝旧的在途上传，避免刚删除的数据立即被旧任务恢复。下一次主动开始同步会重新建立归档。

「重新扫描」清除本机进度而非数据库，适用于读取权限扩展/补录旧数据。UUID 去重，不会因重复同步生成重复样本。健康读取授权结果不可完全获知，空结果不代表权限已允许。撤销读取权限不等同于删除既有服务器数据；需要删除时使用明确的删除功能。活动三环未返回的日期不推断为删除。

## 后台

打开 `/admin/` → **全量健康记录**：默认所有日期，可筛类型、来源、开始与结束日期，加载更早记录并查看 JSON 详情。来源选项的数量和覆盖日期统计符合类型与日期条件的全部记录，不受当前分页或所选来源限制。手机的服务器历史列表也支持按类型加载更早记录。

数据总览/旧上传历史仍然是原来的实时摘要路径，新原始档案不冒充过去日的摘要，也不覆盖今天的眼镜数据。旧趋势不会因导入原始样本自动补齐；历史睡眠每日总时长可先在手机「本机按日查看」读取。原始睡眠有重叠来源和卧床片段，步数也可能有手机与手表重复覆盖，**不能直接 SUM 原始值当成每日结果**。逐样本保留来源；每日总量使用 HealthKit 统计，睡眠日汇总使用既有来源选择/区间去重算法。

“所有”指当前手机健康库中对这些类型已保存且允许 App 读取的记录。不会访问苹果云端直接下载、绕过权限、生成没有记录的睡眠，或恢复从未同步到手机的数据。HealthKit 的数量样本不是原始传感器逐点波形。

## 存储/API

新增（支持既有表前缀）：

- `health_records`：类型+HealthKit UUID 唯一；三环按日期唯一。JSON、起止时间、来源与时区、接收时间；索引支持同时间戳稳定游标翻页。
- `health_history_state`：历史库 epoch。与清空操作事务一致。

接口均保持免 Token、沿用现有来源检查，仅限可信局域网：

- `GET /v1/history/status`：epoch、总量、分类计数和时间范围。
- `PUT /v1/history/batch`：schemaVersion=1、epoch、kind、records、deletedIDs；每批最多 200、请求不超过 1 MiB；同 UUID 更新，删除只按明确 ID。
- `GET /v1/history/records`：kind/sourceID/from/to/limit/cursor，单页 1..100，默认 50；按样本开始日期筛选，应用不设总历史日期上限。`sourceID` 精确匹配保存的来源标识；新增 `sources` 返回全部候选来源的 `sourceID/sourceName/count/earliest/latest`，忽略当前来源与游标，但保留类型和日期条件。旧客户端可以忽略新增字段。
- `GET /api/admin/records` 与 `/api/admin/records/status`：后台同源查看。
- 现有 `DELETE /v1/snapshot`：明确删除**所有摘要与原始历史**，不影响 Apple 健康原始记录，也不自动清除外部备份。

时间保留 UTC 时刻，记录时区优先 HKMetadataKeyTimeZone，缺失时采用导入时手机时区。因此跨时区旅行的无时区样本日期可能与其他软件分组不同。管理页面显示浏览器时区，同时展示源时区。

没有新增身份认证，不要把免登录的详细健康历史服务暴露公网。数据库密码仍需要。本机配置、数据库与真实记录均不能提交到 GitHub。

## 验证范围

自动测试使用人工样本和隔离 MySQL 库，验证多年前导入、同一时间戳分页、重复上传、删除与 epoch、格式/大小校验、后台列表及手机窄屏。iOS 查询与签名、真实健康权限和实际记录数量仍需真机验证。
