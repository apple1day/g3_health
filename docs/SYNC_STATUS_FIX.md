# 0.4.1 (5)：同步成功但首页仍报连接失败

本次仅更新 iPhone 客户端，不修改数据库、后端接口或免 Token 设置。兼容已有 0.4.0 Gin 服务。

## 原因与修复

0.4.0 每日摘要和历史网络请求分别更新 AppModel / HistorySyncModel；历史成功不会清除首页的旧网络错误。摘要请求也把取消、超时、连接中断等都合并成“无法连接”。没有请求回执，不等于服务器没有保存数据。

- 首页和设置使用同一个请求状态源，历史读取/批次上传也会更新最近服务响应。
- 本机健康读取、服务最近响应、每日摘要上传、最近历史批次分别显示，不将历史查询成功当成摘要已上传，也不将一批成功当成全量完成。
- 摘要上传超时/响应丢失后，最多读回一次 `/v1/snapshot`，只有完整解码内容与本次摘要一致才确认成功。更新的时间戳、已有历史条数或健康检查成功都不能替代确认。
- 取消不标记为断网；HTTP 拒绝和传输失败分别记录。真实失败仍显示对应操作和已确认数据，不隐藏错误。
- 切换服务地址、移除配置和删除记录会清理对应状态；旧请求晚返回不能覆盖新地址或新请求的结果。
- 新增“检查服务连接”，仅 GET `/healthz` 并核对响应格式，不上传健康数据。
- 诊断保留错误分类与 URL 错误数字码，不包含地址、凭据、健康数值或响应原文。

## 更新

退出 Xcode，在项目根目录执行：

```bash
git switch main && git pull --ff-only origin main && bash setup-ios.sh
```

保持原 Team 与 Bundle ID，选择实体 iPhone，Command+R 覆盖安装。无需卸载、重新授权、清库或重扫全量历史。确认设置中版本为 0.4.1 (5)。后端保持运行即可，不需要重建或重新初始化数据库。

打开 App 后，状态只描述本次打开以来的已验证请求，不沿用没有服务器标识的旧上传时间。点击“检查服务连接”，再手动同步一次摘要；历史页同步成功后返回首页，应能看到历史批次确认时间，而非旧的全局“无法连接”。

## 测试

新增 RelaySyncStateTests / RelayConfirmationTests 共 26 项：丢失响应后的精确回查、同时间不同内容、较新记录不能证明本次上传、真实失败、取消、HTTP 拒绝、错误回执、只读检查、历史与摘要状态隔离、乱序完成及切换服务地址。全部使用人工数据和 URLProtocol 模拟响应。完整 iOS 编译、原有 HealthKit 计算回归和 Release 构建由仓库 CI 执行；实际设备网络仍需真机验收。
