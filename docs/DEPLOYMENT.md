# 摘要服务部署

本服务是**单用户实例**，保存一份最新摘要；不同使用者应使用独立实例与令牌。API 不提供多账户隔离、公开注册或用户管理。

## 本地验证

使用根目录 `bash start-server.sh`。默认端口 8787。配置来自 `server/.env`；实际数据库默认位于忽略提交的 `server/data/`。HTTP 仅用于同一局域网调试。

令牌需要是不同的高熵值，初始化程序自动生成。上传令牌不能读取，读取令牌不能上传或删除。即使设置开发 CORS `*`，所有健康摘要接口仍然要求对应令牌。

## 公网 HTTPS

1. 选择自己的服务器和域名。
2. 运行 Uvicorn 或 server/Dockerfile，应用端口只开放给反向代理。
3. 在 Caddy/Nginx 等反向代理上配置可信 HTTPS 证书。
4. 配置上传/读取令牌与持久化数据库路径。
5. 配置 `ALLOWED_ORIGINS`，与实际浏览器/Even 插件 Origin 匹配。
6. 将同一个 HTTPS origin 填入 iPhone、插件与插件 manifest 的网络白名单。

Caddy 示例（需替换自己的域名；服务部署在本机 8787 端口）：

```caddyfile
health.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

反向代理需要转发 `Authorization`，并允许 `GET`、`PUT`、`DELETE`、`OPTIONS`。不要启用包含请求头/请求体的调试日志。默认服务已关闭逐请求访问日志，公开 `/healthz` 只提供运行状态和 API 版本。

若平台中的插件 Origin 无法稳定限定，可按 Even 官方网络文档显式配置 CORS `*` 并继续使用 Bearer 身份验证；不要把 CORS 当作身份验证。不要设置 Cookie 凭据。

## 数据生命周期

服务只持有最新快照。新的有效摘要会替换旧摘要，旧时间戳上传返回 409，演示数据返回错误。上传者可以调用 `DELETE /v1/snapshot` 删除当前摘要。操作删除的是该服务的摘要，不影响 Apple 健康里的原始数据。

服务器卷、备份、日志由部署者管理；数据库删除不等于销毁所有磁盘或备份副本。需要结束使用时，一并停止服务、移除数据卷和不再需要的备份，并在客户端清除令牌。

生产环境请将 SQLite 文件置于受控的持久卷；不要把 `server/data/`、`.env` 或真实健康数据提交到这个公开仓库。
