# 0.5.0 (6)：读取、查看和导出 OPPO 等来源的睡眠历史

## 能读到什么

健康速览读取的是 **Apple 健康已经保存、且当前允许本 App 读取的睡眠**。OPPO 健康和健康速览装在同一台 iPhone，并不授予相互读取私有数据库的权限。本版本没有连接 OPPO 云端，也不会把某个 App 图标当作连接成功。

OPPO 的 iOS 4.23 隐私说明列出了通过用户授权向 Apple 健康共享睡眠时长等数据的能力，但没有保证所有版本都回填账号中的全部旧记录、全部睡眠分期。因此，先核对来源和最早日期，再判断可导出的范围。来源列表来自真实 HealthKit 样本；OPPO、HeyTap、OHealth、欢太等文字仅作为候选提示，仍可手动选择任何来源。

## 更新与使用

退出 Xcode，在仓库根目录运行：

```bash
git pull --ff-only origin main
bash setup-ios.sh
```

使用原来的 Team 和 Bundle ID，在 Xcode 中 Command+R 覆盖安装，设置页版本应为 **0.5.0 (6)**。不需要卸载旧 App，也不需要连接服务器来查看或导出本机睡眠。

1. 在 OPPO 健康中打开一条你确定存在的旧睡眠记录，记下日期、开始时间、结束时间，作为核对样本。确认登录的是保存这批历史的同一账号。
2. 在 OPPO 健康的设置中查找 Apple 健康 / 健康数据共享相关选项；具体名称随版本变化。再到苹果「健康」App → 头像 → App 与服务 → OPPO 健康，检查是否提供睡眠写入权限并允许。若根本没有该选项，不应假定此版本支持睡眠共享。
3. 在苹果「健康」App → 睡眠 → 显示所有数据中检查这一天，打开记录核对其来源。健康 App 的图表有睡眠，并不表示一定来自 OPPO。
4. 打开健康速览首页「OPPO / 其他来源睡眠」，点击读取，完成系统的睡眠读取授权。若系统提供历史范围选择，选择你希望允许的范围。
5. 保持手机解锁、App 在前台。扫描完成后选择实际来源，核对样本数、最早和最晚日期，进入某天查看分期与原始记录。
6. 点击「导出 JSON」或「导出 CSV」，通过系统文件保存界面保存。导出只在本机进行，不会触发服务器上传。

若没有读到 OPPO 来源，结果只能说明本次没有返回该来源的可读样本。可能是未共享、未授权、未同步或授权范围不包含旧数据，不能据此断言 OPPO App 或云端没有历史。

## 扫描与导出范围

- 扫描从空 HealthKit 锚点开始，以每页最多 200 个对象继续查询到空页；应用不设置日期下限。实际可读历史由系统授权与已经共享到本机健康库的记录决定。
- 数量是**原始样本条数**，不是睡眠夜数。一晚可能有多条分期、卧床和清醒记录。
- 切入后台或点击停止会请求结束；当前查询可能先完成。已读结果在当前页面内保留，但标记扫描未完成，不能导出为完整扫描。点击「完成」或关闭页面也会请求停止；重新打开页面后需要重新扫描。再次扫描从头核对。
- 导出包含所选来源本次完整扫描得到的全部睡眠样本，不受页面日期筛选影响。JSON 保留原始来源、HealthKit 分类、设备、时区与 UUID；CSV 可用于表格处理。为避免表格把来源文本当公式，CSV 的公式样文本会加单引号，原文保留在 JSON。
- 时间戳导出为带毫秒的 UTC 时间；原始样本时区单独保存。没有时区元数据时，现有读取器采用读取时手机时区，不能反推出当时的旅行时区。
- 日汇总按手机当前时区，以前一日中午到本日中午分组。只使用选定来源，合并重叠睡眠，排除卧床；只有未分类睡眠时不会伪造核心、深度或 REM 分期。跨中午样本可在相邻日明细各显示一次，导出仍按原始 UUID 保留一条。
- 最早和最新时间是**本次读到的覆盖范围**，不代表已经取得 OPPO 云端全部历史，也不证明中间每天都有数据。

原来的首页 / 按日健康摘要继续使用既有单一来源选择规则，Apple Watch 来源优先。新增页面允许明确选择 OPPO 来源，因此不会被同时存在的 Apple Watch 数据遮住。本版本同时收紧了 Apple Watch 设备判断，不再仅凭设备名称含 `Watch` 就把 OPPO / OnePlus 等手表误认为 Apple Watch。

## 可选：同步到自己的后台

如果需要归档到现有 MySQL 服务，可继续使用「历史 → 全部记录与同步」。这会上传受支持类型的逐条记录，和本机睡眠导出是两个独立操作。后台更新仍使用：

```bash
bash setup-backend.sh
bash start-server.sh
```

更新前先停止旧服务进程。保留现有数据库配置；本版本没有增加新的数据库表，也没有改变免 Token 的个人局域网模式。

后台「全量健康记录」新增来源筛选及每个来源的样本数、最早 / 最新时间。统计覆盖符合类型和日期条件的全部已上传记录，不受当前分页或所选来源限制。接口 `GET /v1/history/records` 和 `GET /api/admin/records` 新增可选精确匹配参数 `sourceID`，响应新增 `sources` 列表，旧客户端可忽略。筛选日期沿用样本开始日期；它和手机中午到中午的睡眠统计日不是同一口径。

## 苹果健康没有这些旧记录时

增加 HealthKit 读取代码不会创造 OPPO 尚未共享的历史。这时可尝试：

1. **申请个人信息副本**：通过 [欢太隐私反馈入口](https://brand.heytap.com/cn/privacy-feedback.html) 申请本人 OPPO / 欢太健康账号的睡眠历史副本，说明日期范围，并要求机器可读格式、起止时间、时区和分期（如平台保存）。申请结果、可提供字段与格式由对方确认；不能保证返回可直接导入的文件。
2. **已有 Root 环境的 Android 设备**：第三方项目 [OHSync](https://github.com/bqj6666/OHSync) 与 [oppo-health-export](https://github.com/foxlesbiao/oppo-health-export) 尝试通过 LSPosed 读取本机 OPPO 数据库。它们依赖 Root、框架、OPPO 版本与实际下载到本机的历史，本项目没有集成，也未用你的账号或设备验证。它们不等于无需授权的公开云端 API。

如果拿到实际导出文件，可据其字段再实现导入。当前没有凭空假定 OPPO 导出格式，也没有声称已经实现云端历史下载。
